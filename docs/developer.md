# Developer Guide

## Setup

```bash
pnpm install
pnpm --filter @mun/protocol build
pnpm --filter @mun/crypto build
```

The shared packages emit `dist/` which the apps resolve via node_modules. **Build
the shared packages after changing them** before type-checking/building the apps
(or run `pnpm build` which orders packages first).

## Common commands

```bash
pnpm typecheck              # typecheck every package
pnpm test                   # run every test suite
pnpm build                  # build packages then apps
pnpm server:dev             # server with tsx watch (hot reload)
pnpm desktop:dev            # Electron + Vite renderer (hot reload)
pnpm migrate                # apply DB migrations
SEED_DEMO=1 pnpm seed       # seed demo committee + delegates
pnpm format                 # prettier
```

## Conventions

- **TypeScript strict** everywhere; `noUnusedLocals` on for packages/server.
- Shared types live in `@mun/protocol`; never duplicate wire types in an app.
- Zod schemas mirror the types and validate at every trust boundary (server
  inbound, client inbound). Enum schemas are suffixed `*Schema` so they don't
  clash with the type unions of the same name re-exported from the barrel.
- The renderer has **no Node access**. It talks to the main process only through
  `window.mun` (preload bridge). Chair/admin REST actions go through
  `api.apiRequest`, which the main process proxies with the stored token.
- Timestamps are integer milliseconds since epoch, stored as `BIGINT` in Postgres
  (pg returns bigint as strings — always wrap reads with `Number()`).
- Append-only tables (`audit_log`, `vote_records`) have triggers forbidding
  UPDATE/DELETE. The audit chain needs `seq` known before insert, so
  `audit_log.seq` is `GENERATED BY DEFAULT AS IDENTITY` and appends are
  serialised by an advisory lock.

## Adding a new AI service

Admin screen → AI Rules → Add (no recompilation). Or insert into
`ai_detection_rules` directly. The rule syncs to all delegates via
`rules_updated` over WebSocket. Add a built-in seed rule in
`packages/protocol/src/rules.ts` (`BUILTIN_AI_RULES`) if you want it pre-seeded.

## Adding a new WebSocket message type

1. Add the type + payload to `packages/protocol/src/messages.ts`
   (`ClientPayloadMap` / `ServerPayloadMap` + the `CLIENT_TO_SERVER` /
   `SERVER_TO_CLIENT` sets).
2. Add a Zod schema in `schema.ts` if it carries inbound data.
3. Handle it in the server (`realtime/ws.ts`) and/or the desktop
   (`realtime/client.ts` dispatch + `store.ts` `dispatchEvent`).
4. Rebuild `@mun/protocol` (`pnpm --filter @mun/protocol build`).

## Adding a server migration

Create `apps/server/migrations/00N_name.sql` (numbered, sorted). The migration
runner applies pending files in order and records them in `_migrations`. Keep
migrations immutable once deployed.

## Desktop main process is CommonJS

Electron 33's Node 20 has an ESM-main bug (`cjsPreparseModuleExports` crash on
`import { app } from 'electron'`), so the desktop builds as CommonJS
(`apps/desktop/package.json` has no `"type": "module"`). The renderer is a
separate Vite build (ESM in the browser) and is unaffected. `@mun/protocol`,
`@mun/crypto`, and `ws` are bundled into the main (not externalized) to avoid
Electron's ESM-CJS resolution edge cases; `koffi` and `ws`'s optional native
addons stay external.

## Launching the desktop in a sandboxed shell

If `ELECTRON_RUN_AS_NODE=1` is set in the environment, Electron runs as plain
Node and the GUI won't start. Unset it for the launch:

```bash
env -u ELECTRON_RUN_AS_NODE pnpm --filter @mun/desktop dev
```
